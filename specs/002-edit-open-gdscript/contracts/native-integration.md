**Status (2026-09-28):** [§17 M3 / F-blocking](../research.md#17-minimal-behavioral-finalization-research-2026-09-28) rejects the **tested guarded no-handler direct CodeEdit tag** as a saved-state solution: immediate independent D/R/B=23, `6/6` clean, edited=false does **not** prevent a false external-change dialog on a later ordinary human Save, which leaves D23/newer human B29 unsaved; corrected Undo → Save → Redo → Save also fails at the first Save and adds an observed later history step. No bounded supported narrow repair was established. [§14 P1](../research.md#14-stock-post-persistence-saved-transition-research-2026-09-28) remains a **held saved-state-only native-handler candidate**, **not** an admitted safe production route: [§16 H3](../research.md#16-stock-saved-handler-admission-research-2026-09-28) found no useful safe admission profile for that handler's tested stock/public-observer composition. Neither failure proves all handler-free routes impossible or full-handler necessity. Primitive B's read-only validation was implemented and runtime-verified in patched-editor [T002](../quickstart.md#10-t002-native-validation-acceptance-2026-09-28) as an oracle/hazard inventory, **not** a production patched dependency or stock validator; an explicit exact-source stock validator is independently unresolved. ## 1. Ownership and minimum exposure

**Held P1 saved-state design, not an implementation or a proof it is necessary:** The product target remains official stock Godot plus addon and bundled standard public-ABI C++17 GDExtension. Existing editor integration/private bridge own admission/routing; native code would own one complex text edit, explicit bound `Script.set_source_code`, and one descriptor-bound target writer. The §14 P1 candidate follows persistence with public edited-state methods and the already connected native ScriptEditor callback captured via public incoming-signal introspection. §17's independent no-handler experiment instead used the public CodeEdit tag directly and failed later ordinary Save/history. Neither is selected for T003 implementation without complete behavioral/effect proof. A patched engine, custom editor/saver, current-tab Save, broad Save or new dedicated stock finalization API is not a fallback. Exact-source validation and effect confinement remain separate.

T002 exposed the narrower `GDScript.gdscript_validation_api_revision()` and `validate_gdscript_source` ClassDB bindings plus `ScriptEditorBase.get_edited_resource()` association readback in its patched editor. No generic object-call, filesystem, evaluator or history-control API is granted to bridge/caller. Stock public observation instead reads the actual still-open association, `EditorInterface.is_object_edited(Script)`, CodeEdit current/saved versions and dirty state, and independent D/R/B; it does not numerically inspect or set private Resource mtime or document mtime. §17 demonstrates document timestamp freshness has a real later Save consequence without making private numeric parity a requirement.

Preparation also inspects the target's native save-format settings and checks both the baseline and desired source against the same engine formatting rules in a non-mutating/check-only path. `save_current_script` runs `_auto_format_text` (trailing whitespace, final newlines and indentation); a later Save must not silently change the promised revision or destroy the Undo → Save → Redo case. Return `unsupported_representation/save_would_reformat` if either source would change, or if the relevant behavior cannot be established. Retain/recheck this fixed save-profile witness at application and verification. Never alter editor preferences, run formatting on the live document, or add a general formatter API. Representation limits are explicit; later independent human source/settings changes remain outside the successful interval.

The candidate guard is an attempt-local binding of request/session, actual document objects, source/versions, receipt and, **for held P1**, Callable topology; it is **not** a new engine guard object or transaction/session UUID. Establish binding/receipt/version guards immediately before each native effect; for P1 specifically recheck between edited-flag clearing and callback invocation. It does not lock out human work or serialize external filesystem writers; identity/source/version changes invalidate it rather than trigger repair. Intermediate D/R/B divergence is allowed with protected boundaries, accurate partial-result classification and independent final observations; no global every-step atomicity claim. Separate exact-source validation/effect coverage must be established before T003 implementation.

Kit admission remains the integration's existing single active collection/edit slot, not a second native scheduler or lock policy. Only its current attempt may invoke effectful native stages; a rejected overlap has no native work to resume after release. Caller termination does not release the slot/handles while entered native work can still mutate: stop new stages and complete safe cleanup under [NativeAttempt](../data-model.md#nativeattempt) before another attempt is admitted. Human typing remains possible; never merge or rebase competing intentions.

## 2. Common bound state and persistence receipt

Every native operation belongs to one authenticated connection, existing `request_id`, selected `session_id`, canonical project directory identity, and exact `res://` standalone `.gd` path. Document identity comprises actual Script, ScriptEditorBase and CodeEdit instance IDs plus their current association. Retain the Script reference; revalidate node IDs/open-document association before dereferencing editor objects. A retained Resource is not proof the document remains open.

The native attempt retains the expected baseline and immutable desired UTF-8 source, independent source hashes, post-application current buffer version, independently observed preparation-time saved version, expected R source, exact bound Script/editor/CodeEdit IDs and association, and one target file descriptor opened relative to the validated project directory. **Held P1 alone** additionally retains the actual captured callback edge/Callable. Observation v1 supplies no prior saved-version witness; preparation obtains it directly and unexpected retagging before finalization invalidates the attempt. Root/leaf identities must match the Rust-observed identities; no caller-supplied absolute destination is used. Component traversal uses existing confinement/owner/permission/ACL rules and no-follow existing-file opens. No create/truncate happens during preparation.

**Native-only PersistenceReceipt:** the descriptor writer creates this attempt-local record after the actual write, never from a client-supplied `saved` flag. It records:

- request/session/document binding and desired source hash/UTF-8 length;
- project and opened-file device/inode identities, retained descriptor ownership;
- `write_started`, bytes written, truncate completion and flush completion;
- descriptor readback identity/content result and current project-path attachment result;
- descriptor-observed modification time as a persistence fact, **not** a supplied or required private Resource/document mtime setting;
- known interference, elapsed/interval evidence and explicit error/unknown states.

Only a complete successful write/truncate/flush/readback with unchanged binding and current namespace attachment is eligible for the saved transition. Receipt facts are **application evidence**, not the independent Rust D observation. A proof for another attempt/document, a closed descriptor, incomplete write/flush, unknown result, or detected revision/namespace change is ineligible. The receipt is used once, released with the attempt, and never persisted or accepted on the wire as authority.

The writer rechecks expected D bytes/identity and the current B/R/identity guards before I/O; it writes only the retained file object. Short writes are completed only while the same attempt remains eligible; any later error preserves actual byte/application facts. Empty replacement still performs the required truncate/flush. Recheck path attachment and source afterward. Namespace loss is non-success even if the original renamed/unlinked object received bytes; never reinstall it. This is not crash-atomic storage or arbitrary same-inode compare-and-write. Known interference always prevents success.

The earlier patched candidate used receipt-fed private mtime fields and an engine hook that tagged CodeEdit **last**; it remains historical, not the current stock requirement. [§13](../research.md#13-stock-target-save-finalization-research-2026-09-28) established that a custom saver returning non-OK cannot veto builtin path fallback (even an outside-project redirect), ordinary target Save applies all open scripts and may change unrelated history, and descriptor-backed `ResourceSaver.save` lacks ScriptEditor's document transition. [§14](../research.md#14-stock-post-persistence-saved-transition-research-2026-09-28) demonstrates the bounded direct existing-Callable candidate **after** descriptor persistence, still held by H3. [§17](../research.md#17-minimal-behavioral-finalization-research-2026-09-28) demonstrates the different **no-handler** direct CodeEdit tag is insufficient for actual later Save/history under a natural timestamp-second change, not that every no-handler alternative fails. Neither ordinary Save, custom saver nor signal broadcast qualifies as a fallback.

## 3. Primitive A: guarded target-document saved transition

### Existing public ingredients and preconditions

Here "A" means attempt-owned **semantic** finalization, not `finalize_script_document(...)`, a new dedicated stock API, a private-method call by name, or a finalized native/bridge result schema. **Only for held P1**, on the pinned official engine build obtain canonical ScriptEditor with `EditorInterface.get_script_editor()` and inspect its public `Object.get_incoming_connections()` for the unique already existing incoming `resource_saved` Signal and Callable whose receiver is that exact ScriptEditor. Retain the actual emitter Signal and Callable; verify `Signal.get_object()/get_name()`, `Callable.get_object()/is_valid()`, receiver instance IDs, incoming edge and emitter `get_signal_connection_list` before use. The observed emitter is EditorNode (flags `0`); reflected handler method metadata identifies `ScriptEditor::_res_saved_callback` **for audit only**. Never resolve or invoke that private method by string, use a binary symbol/private layout, walk an assumed editor-tree hierarchy, emit `resource_saved`, or invoke arbitrary connected listeners. P1 calls only the **publicly returned actual Callable** with the exact held Script; §17's candidate never obtains one.

For held P1, before clearing the edited flag, establish all of:

1. The original authenticated connection/request/session/attempt slot is live and not expired, cancelled or consumed; the Script, ScriptEditorBase and CodeEdit retain the same instance IDs, resource path and unique still-open association. A retained Script or same-path reopened tab alone does not authorize tagging.
2. B has exactly the frozen post-complex-edit current version **and** desired text, and the frozen independently prepared saved version is unchanged; R is the exact intended source on the same Script. Equal text on a newer version is not enough.
3. The same attempt's native-only receipt proves complete descriptor write/truncate/flush/readback of the intended source; current no-follow project-path namespace attachment and target identity/source checks still hold. Failed, unknown, mismatched or lost-namespace persistence cannot authorize a tag.
4. The captured native edge/Callable still has its exact canonical receiver/emitter/topology and is valid; the held Script is the exact cached target, not a candidate that would require `ResourceLoader` fallback. Exclude any open built-in sibling Script with a parent-path collision: the stock handler may also tag/reload such documents. Capture/recheck the save-format profile and refuse unsupported document/effect topology conservatively.

### Held P1 order and effects (not a production requirement for every future route)

R synchronization precedes persistence and A: after **one** native CodeEdit complex text operation, compare B/current version and expected original R, call the bound `Script.set_source_code` method with the intended text, and read R back. Do not assign via `Object.set`/GDScript `_set` (which can reload), invoke `ScriptTextEditor::apply_code`/`update_exports`, or apply pending dragged-export properties. Descriptor-bound persistence follows; no additional source write occurs during the saved transition.

After all fresh guards pass, call `EditorInterface.set_object_edited(Script, false)` for the persisted guarded R, then **recheck** the entire still-open/identity/path/source/current-and-saved-version/receipt/namespace/cached-Script/edge binding immediately before direct `Callable.call(Script)`. Do not yield, pump events, focus/select a tab, issue a second write, dispatch a save or broadcast a signal between final guard and the native tag. The public edited setter has no intervening user callout in the tested route; retain a bounded, version-specific topology and reentrancy check rather than assuming arbitrary stock builds are safe.

The **stock native handler** matches the Script's actual edited Resource pointer and executes its combined target document tag: **CodeEdit current saved version first**, then ScriptEditorBase document `last_modified_time` from `FileAccess::get_modified_time(actual path)`. The guarded route does not supply a timestamp to private fields, change Resource path/cache identity, modify CodeEdit text/history, or numerically set/read Resource mtime. Its list-name refresh is **not UI-only**: the names tail enters `_update_members_overview` and `ScriptTextEditor::get_functions`, validating the **current** editor's B/path, which may be the target. Later validation `name_changed` can repeat discovery for a different current editor. Never focus/select the target as an operation-time workaround. Path attachment is checked immediately before and independently after: external writers cannot be atomically excluded, and a later namespace loss prevents success.

This handler is **not pure or callback-free** after the native tag. It invokes `trigger_live_script_reload`: with an exact cached Script it can immediately run native language validation/dependency/cache paths even when runtime auto reload is disabled, record the path, and conditionally defer shared debugger reload; the names tail can also validate the current editor as described above. A missing cached target could instead enter `ResourceLoader` fallback and must be refused. Metadata=false and an unchecked native menu item are **not** a witness that effective scheduling is disabled: §16 observed actual runtime 17→31 in that state. Native menu actions in disposable setup bounded effective off at 17 and on at 31; they are not a product safety mechanism, and public session observation is not a version-bound completion token. No running-game hot-reload, unrestricted validator safety, effects confinement, export/Inspector refresh or project-wide compilation guarantee follows from the saved-state proof. Independent stock callback admission and explicit-validation requirements keep T003 on hold. The narrower no-interstitial-callout claim is only **before/between** the stock CodeEdit/document tag operations on the audited build.

The separate §17 candidate used the guarded native edit → explicit R setter → descriptor D receipt, with exact binding/source/version/namespace checks **but without any P1 handler-edge guard**, then edited=false → renewed guards → **direct public CodeEdit saved-version tag → STOP**; it **never discovered or invoked** a saved-handler Callable. Its immediate clean public state is not a final saved-state proof: a later delivered ordinary Save falsely requests external-change reconciliation and cannot persist newer human B; native Undo → Save likewise fails. This failure does not retroactively prove P1's callback tail necessary or safe. For any supported future route, accept **behavioral** saved-document coherence and prevent forbidden effects before dispatch; do not require full native Save callback history, private Resource/document numeric mtime parity, internal cache-generation parity as an end in itself, or automatic running-game hot reload. Actual consumed-generation attribution remains necessary for explicit validation/forbidden callbacks where relevant.

### Results, independent observation and failure

For **held P1**, record attempt-local observed facts: edited-flag clear, fresh pre-Callable guard, whether Callable was entered/returned, CodeEdit current/saved versions, dirty state, D/R/B/identity/attachment and errors/unknowns. `complete`, `rejected` and `partial_or_unknown` describe a candidate A stage only, not edit success or a new final API shape; even `complete` immediate readback does not discharge later Save/history. A rejected finalizer can follow changed B/R/D. A setter that succeeds before an invalidated recheck is **partial**; never report no bookkeeping or retry old intent. A tag followed by new human text leaves the new buffer dirty; never restore, replay or overwrite it. Any future alternate route owes the same truthful applied/partial/non-success semantics without copying P1's unnecessary callback steps.

| Condition | Required result |
|---|---|
| Closed/replaced document, wrong Script/editor/CodeEdit, edge or cached Script, colliding built-in association | Reject before bookkeeping; if detected after edited-flag clearing, report partial. Never retarget. |
| Changed current **or** saved version, even equal desired text; newer human B or unexpected R | Refuse the tag, retain newer state; D may already have changed. |
| Failed/missing/unknown/mismatched receipt or changed/lost namespace | Refuse the tag without a saver fallback or replacement write; preserve actual application facts. |
| Reentrant work, cancellation or deadline before A | Refuse without starting bookkeeping; any later invalidation retains established effects. |
| Later invalidation/failure, including after a tag or stock handler effect | Report partial/unknown with observed steps; no rollback or cleanup write. |
| All bounded P1 tag guards/effects and immediate independent readbacks pass | Only a **candidate immediate saved-state witness**. Before a route can qualify, later ordinary human Save, Undo → Save → Redo → Save, reopen/durability, unrelated effects and separate exact-source validation/effect confinement must also pass. Rust's final reducer still gates edit success. |

After candidate A, independently read actual still-open association, `EditorInterface.is_object_edited(Script)`, CodeEdit current/saved versions and dirty state, actual R/B and Rust's fresh D/namespace evidence; do **not** substitute Callable return, direct tag or edited-flag setter acknowledgment. Neither private Resource/document numeric mtime equality nor “complete native bookkeeping” is a goal. Document mtime freshness **has concrete behavioral relevance** on the tested natural timestamp-second crossing: direct tag without the document's matching timestamp behavior led to a false later Save dialog. §14 P1's standalone positive Save/reopen observations remain bounded; §17's no-handler later-Save/Undo failures prevent claiming a direct-tag solution. The desired proof is correct ordinary Save/history/reopen with protected user/unrelated state, not a particular private-field mechanism.

## 4. Primitive B: exact-source native GDScript validation

The following specifies required validation behavior and records T002's completed patched-editor semantic oracle/reference and hazard inventory; the example native binding below is **historical**, not a selected stock method, implementation shape or final wire schema. P1 demonstrates bounded saved-state mechanics but remains held under H3; the §17 no-handler candidate fails ordinary later Save/history. [§15](../research.md#15-stock-validation-and-effect-confinement-research-2026-09-28) posed the historical callback admission question; [§16](../research.md#16-stock-saved-handler-admission-research-2026-09-28) found no useful safe accepting profile for the demonstrated composition, not impossibility for every future design. A qualifying explicit exact-source stock validator is independently unselected/unproved. Neither callback research, §17 nor T002 patched acceptance discharges that separate parser/analyzer/diagnostic proof obligation; genuine forbidden-effect boundaries are unchanged.

### Inputs and output

`validate_gdscript_source(source, source_path, read_context, correlation)` runs synchronously on the selected editor main thread. Inputs are an immutable exact source string, exact project-confined `res://` root path, a native-only selected-project read context, and existing request/session/document identity plus purpose `preflight`, `post_change` or `unchanged`. No mutable global buffer is the implicit input. Compute SHA-256 from the actual supplied UTF-8 bytes; compare the integration's expected hash before invocation. The root target is already open/loaded; validation does not open or load it.

The **historical T002** engine exposure delegated to `GDScriptLanguage::validate` → `GDScriptParser::parse(source, path, false)` → `GDScriptAnalyzer::analyze` with the scoped effect/dependency policy below and returned actual root/dependency `ScriptError` records. Stock must still produce real completed parser/analyzer semantics; no stock binding, helper or source port is selected, and reload, `can_instantiate`, log silence or empty diagnostics are not validity witnesses.

Return exactly one status:

- `valid`: the requested parser/analyzer stages completed under the selected policy for this exact source/context, without errors.
- `invalid`: a completed validation rejected this source/context; retain root/dependency diagnostics and the failed parser/analyzer stage when supplied.
- `unavailable`: invocation incomplete, context/attribution invalid, disallowed effect, access failure, resource bound, wrong thread or reentrant invocation. Partial diagnostics do not turn it into valid/invalid.

Every result includes request/session/document binding, purpose, actual input path/hash/byte length, editor-clock start/end ticks, result/reason, dependency/context witnesses and `diagnostics_complete`. Diagnostics carry `origin: root|dependency`, confined path (or null with reason), source hash when actually read, line/column when supplied, category and message. Unknown dependency source is not assigned the root hash. Missing dependency proven by a confined read can yield a completed dependency error; an unreadable or unconfined dependency yields unavailable. Redact denied/outside-project paths; never disclose their source or raw absolute paths. Errors/messages appear only in the requested result, not incidental logs.

Limits: root and each dependency ≤512 KiB UTF-8; at most 32 distinct source dependencies / 4 MiB dependency bytes; at most 64 error records with messages ≤2048 UTF-8 bytes and paths ≤2048 bytes. Exceeding a needed bound yields `unavailable` with limit reason and safely retained partial diagnostics, not truncated source or false valid. Warnings/functions/safe-line UI data are not a new caller diagnostics API.

### Required effect policy: source analysis, not arbitrary evaluation

Allow the existing parser/analyzer, engine-native static type metadata, current project/global-class/autoload mapping lookup, confined read-only GDScript dependency text, normal parser/dependency-cache lookup/population and dependency-edge bookkeeping. Cache mutation is expected engine bookkeeping, not a purity failure. Do not clear global caches to simulate isolation.

T002 implemented a **patched-editor validation-call-scoped read/effect context** through the implicated GDScript parser/cache/analyzer paths and proved its confined dependency/effect behavior in 54 native cases. It is a completed semantic oracle/reference and hazard inventory, not a product patch or qualifying equivalent in official stock Godot. The following policy remains an independent stock requirement; it does not prescribe porting the patch or introduce a stock public guard API:

1. All dependency bytes are obtained through the trusted native integration's project-directory capability reader, with no-follow traversal and before/after identity/content checks. Resolve each relative dependency against the directory of the source containing that reference: the supplied root path for root references, and Godot's per-dependency source paths for transitive references. Resolve permitted project mappings to a confined `res://` path before reading. No absolute/user/network/embedded/remapped-outside-project fallback. Unsupported binary/remapped dependency representations are unavailable, not silently loaded.
2. A cache hit is usable only when attributable to the same project/path and current guarded input digest. A current `Script.source_code` getter does not prove cached parser/analyzer/shallow metadata was derived from that source generation. Stale/unattributed metadata cannot certify the proposed source. T002 used engine parser types and call-local references to analyze the root overlay/current dependency bytes without replacing the loaded Script or clearing global caches; that is reference behavior, not a selected stock port. A stock solution must independently account for cache provenance and fresh per-call read witnesses.
3. Permit shallow GDScript metadata construction only without full reload, script instantiation or initialization. Prevent non-GDScript `ResourceLoader` resolution **before** invoking loaders (including exists/type hooks), full-script loading, and dynamic object-property `Variant::get/get_named` paths. An unadmitted path returns `unavailable/unsupported_effect` rather than invoking project code. Plain built-in value operations and engine-native static metadata remain allowed. Do not substitute guessed types or skip analysis and return valid.
4. No user method, tool/static initializer, scripted constructor/getter, arbitrary loader/callback, process/network action, source write, root R/B assignment, document save or project scan is permitted as an effect of this call. `@tool` syntax alone is not execution or an automatic rejection; a resolution path requiring an excluded effect is. Unsupported effectful validation is a truthful capability refusal, not a new evaluation permission prompt.
5. Capture and recheck dependency identities/hashes and relevant project/class/autoload/remap context used by the invocation. Changed/missing witnesses make the result unavailable/invalidated. The result describes an observed context, not an atomic snapshot or project-wide compilation.

T002's patched GDScript-owned validator reused Godot's parser/analyzer rather than building a second compiler; its patched-editor acceptance remains complete. On stock, public ClassDB/native class, global-class and autoload mapping metadata is available, but demonstrated metadata samples do not prove analyzer parity or current live-editor generation. `reload(false)` omits export refresh, **not** parsing/analysis/compilation or conditional static initialization. In the measured `--headless --check-only --script` helper, source is fully loaded before EditorNode disables scripting even with `--editor`: tool and non-tool static initializers executed, and all observed invalid cases exited 0. Neither exit status/log silence nor broad reload qualifies as an attributed valid/invalid/unavailable result. Restricted helper/source eligibility and public-ABI parser/analyzer adaptation remain unselected, unexhausted design-review alternatives; a conservative source scanner can refuse hazardous syntax but cannot certify semantics, and does not silently turn `@tool` alone into a rejection rule. What remains unproved is both a stock explicit validator satisfying the above result contract **and**, separately, safe admission of ordinary/edit-generated validation and export work, the native saved handler's validation/deferred reload, and queued effects on attributed dependency generations. The bridge cannot supply executable read callbacks. Existing exclusion of hostile code already executing inside the editor/same-UID malware remains unchanged.

### Guarding the ordinary editor path

The historical companion engine guard was proposed because successful ordinary non-tool `_validate_script` can copy B into R and call `update_exports`; `apply_code` and export propagation can assign source/export state and pending dragged properties. `get_functions` independently validates B, **and the saved handler's own names-refresh tail can reach `get_functions` for the then-current editor**. This does not say the handler unconditionally refreshes target exports; ordinary validation/export is a distinct continuation and a later `name_changed` can repeat current-editor discovery. Held P1 has **no** stock engine guard. Any route must account for ordinary edit-generated validation/export and actual current-editor effects; **if invoking the saved handler**, additionally prove immediate `trigger_live_script_reload` validation/cache and conditional deferred debugger routing without switching focus to the target. Explicit supported `Script.set_source_code` remains the only planned R synchronization step.

The §16-tested source/context closure establishes **no accepting admission rule for P1's saved-handler composition**. Before any mutation or forbidden dispatch **if that callback path is used**, a supported route would have to attribute actual consumed root/dependency/parser/shallow/export generations (including historical reverse export consumers), constrain current-editor function discovery and ordinary validation/export callbacks across later `name_changed`, and account for shared deferred runtime routing/completion under session changes. A current Script getter, public method list, hash of disk bytes, source restrictions or validation-signal count is not a consumed-generation witness; same-path stale compiled metadata with current-disk diagnostics did **not** demonstrate stale parser consumption. A later reentrant/dependency write cannot be excluded by a single final guard, nor can an entry-time inactive session or callback return prove later deferred runtime safety. Metadata/menu false does not prove native scheduling disabled; even actual effective off does not suppress immediate native validation or cancel previously queued work. Preserve newer independent human changes on normal Godot handling; do not globally disable validation, block typing, rewrite text, focus target or clear unrelated state. Any route must prevent forbidden agent-initiated callback effects **before** execution; no agent-initiated callback may mark B saved outside the guarded post-persistence transition. Independent human Save retains normal behavior.

Inability to establish stock explicit validation **or** a useful safe stock callback admission profile is a non-success/unsupported implementation result, not permission to proceed. A restricted helper or pinned-source adaptation for explicit validation alone cannot intercept existing native editor callbacks. Conservative source refusal may reject unknown cases, but §16's tested meaningful preload/literal-extends source/context profile did not establish safe acceptance; it is not a selected predicate, a second semantic parser or an `@tool`-only policy. The historical patched hooks and an unproved separation/replacement of the handler's unsafe tail are not T003 fallbacks.

### Placement in the edit flow

For changed intent, run B on proposed source during preparation to refuse invalid/unsupported-effect inputs before changing B or history. Then freshly recheck mutation guards; preflight is not permission for a delayed edit. After source application, persistence and a **qualified behavioral A** (not merely §17's immediate clean readback), read actual resulting B/R and invoke B again with that exact source as `post_change`. This second result is the required post-change parse witness. Dependency/context changes can still produce invalid/unavailable after earlier valid; report applied-unverified and do not force convergence. The sequence does not require P1's handler/Callable for every conceivable qualifying A, but a no-handler A must first solve §17's measured ordinary Save/history failure.

For unchanged requests, skip proposed-source preflight and run one `unchanged` validation with independent verification, without native text mutation, writer, finalizer, saved tagging or history entries.

## 5. Implementation proof obligations

The [quickstart](../quickstart.md) supplies the acceptance matrix.
