**Status:** Primitive B's read-only validation was implemented and runtime-verified by [T002](../quickstart.md#10-t002-native-validation-acceptance-2026-09-28) in a patched editor; that historical acceptance remains complete, but does not establish a qualifying stock validator. T003 remains on hold for independent stock exact-source validation/effect confinement and design review. The [data model](../data-model.md) owns common field meanings; Rust/core alone classifies terminal outcomes.

## 1. Ownership and minimum exposure

**Selected saved-state design, not an implementation:** The product target is official stock Godot plus addon and bundled standard public-ABI C++17 GDExtension. Keep the existing editor integration and private bridge for admission/routing; native code owns one complex text edit, explicit bound `Script.set_source_code`, and a descriptor-bound one-target writer. After persistence, use existing public edited-state methods and an already connected native ScriptEditor callback, captured via public incoming-signal introspection. No patched engine, custom editor, custom saver, current-tab Save or new dedicated stock finalization API is selected. The separate parser/dependency/effect-confinement problem remains open.

| Responsibility | Owner / selected mechanism |
|---|---|
| Intent, stale/conflict policy, authorization, deadlines, uncertainty, final classification | Existing Rust library and supervised caller/worker. |
| Authentication, routing, connection/attempt lifetime, marshaling | Existing private bridge and Godot integration. |
| Native complex text operation, explicit Script source setter, descriptor-bound I/O | Standard GDExtension through supported object methods and current-platform OS APIs. |
| Guarded saved transition and independent public saved-state evidence | Attempt-owned guards and receipt; `EditorInterface.set_object_edited(Script, false)` followed by the **actual existing** ScriptEditor native handler Callable obtained from canonical ScriptEditor's public incoming `resource_saved` connection. Public edited flag, CodeEdit versions/dirty, exact association and D/R/B are independently observed. No private numeric Resource/document mtime getter/setter is selected. |
| Exact-source validation and restricted dependency/effect handling | Independently unresolved for stock; T002 proved the patched GDScript-owned engine validator, not stock availability or effect confinement. |
| Target-local guarding of automatic validation caused by the agent edit | Independently unresolved stock validation/effect requirement; do not assume the historical engine guard exists. |

The earlier proposed engine API family revision **1** (`inspect_script_document`, `begin_script_edit_guard` / `end_script_edit_guard`, `finalize_script_document`, `validate_gdscript_source`) and private numeric inspection/bookkeeping were a patched-engine design, **superseded for selected stock saved-state finalization**, not stock bindings to implement on T003. T002 exposed the narrower `GDScript.gdscript_validation_api_revision()` and `validate_gdscript_source` ClassDB bindings plus `ScriptEditorBase.get_edited_resource()` association readback in its patched editor. Its editor-local metadata reports **validation** revision `1`, not this whole family or edit capability; see the [implemented native surface](../../../godot-addon/native/README.md#integration-surface-and-acceptance). No generic object-call, filesystem, evaluator or history-control API is granted to bridge/caller. Stock public observation instead reads the actual still-open association, `EditorInterface.is_object_edited(Script)`, CodeEdit current/saved versions and dirty state, and independent D/R/B; it does not numerically inspect or set private Resource mtime or document mtime. The native document timestamp update has bounded behavioral evidence from later Save/reopen, not numeric private-field readback.

Preparation also inspects the target's native save-format settings and checks both the baseline and desired source against the same engine formatting rules in a non-mutating/check-only path. `save_current_script` runs `_auto_format_text` (trailing whitespace, final newlines and indentation); a later Save must not silently change the promised revision or destroy the Undo → Save → Redo case. Return `unsupported_representation/save_would_reformat` if either source would change, or if the relevant behavior cannot be established. Retain/recheck this fixed save-profile witness at application and verification. Never alter editor preferences, run formatting on the live document, or add a general formatter API. Representation limits are explicit; later independent human source/settings changes remain outside the successful interval.

The selected guard is an attempt-local binding of request/session, actual document objects, source/versions, receipt and topology, **not** a new engine guard object or transaction/session UUID. Establish it immediately before each native effect and recheck between edited-flag clearing and callback invocation. It does not lock out human work or serialize external filesystem writers; identity/source/version changes invalidate it rather than trigger repair. Separate automatic validation/effect coverage must be established before T003 implementation.

Kit admission remains the integration's existing single active collection/edit slot, not a second native scheduler or lock policy. Only its current attempt may invoke effectful native stages; a rejected overlap has no native work to resume after release. Caller termination does not release the slot/handles while entered native work can still mutate: stop new stages and complete safe cleanup under [NativeAttempt](../data-model.md#nativeattempt) before another attempt is admitted. Human typing remains possible; never merge or rebase competing intentions.

## 2. Common bound state and persistence receipt

Every native operation belongs to one authenticated connection, existing `request_id`, selected `session_id`, canonical project directory identity, and exact `res://` standalone `.gd` path. Document identity comprises actual Script, ScriptEditorBase and CodeEdit instance IDs plus their current association. Retain the Script reference; revalidate node IDs/open-document association before dereferencing editor objects. A retained Resource is not proof the document remains open.

The native attempt retains the expected baseline and immutable desired UTF-8 source, independent source hashes, post-application current buffer version, independently observed preparation-time saved version, expected R source, exact bound Script/editor/CodeEdit IDs and association, the captured actual native callback edge/Callable, and one target file descriptor opened relative to the validated project directory. Observation v1 supplies no prior saved-version witness; preparation obtains it directly and unexpected retagging before finalization invalidates the attempt. Root/leaf identities must match the Rust-observed identities; no caller-supplied absolute destination is used. Component traversal uses existing confinement/owner/permission/ACL rules and no-follow existing-file opens. No create/truncate happens during preparation.

**Native-only PersistenceReceipt:** the descriptor writer creates this attempt-local record after the actual write, never from a client-supplied `saved` flag. It records:

- request/session/document binding and desired source hash/UTF-8 length;
- project and opened-file device/inode identities, retained descriptor ownership;
- `write_started`, bytes written, truncate completion and flush completion;
- descriptor readback identity/content result and current project-path attachment result;
- descriptor-observed modification time as a persistence fact, **not** a supplied or required private Resource/document mtime setting;
- known interference, elapsed/interval evidence and explicit error/unknown states.

Only a complete successful write/truncate/flush/readback with unchanged binding and current namespace attachment is eligible for the saved transition. Receipt facts are **application evidence**, not the independent Rust D observation. A proof for another attempt/document, a closed descriptor, incomplete write/flush, unknown result, or detected revision/namespace change is ineligible. The receipt is used once, released with the attempt, and never persisted or accepted on the wire as authority.

The writer rechecks expected D bytes/identity and the current B/R/identity guards before I/O; it writes only the retained file object. Short writes are completed only while the same attempt remains eligible; any later error preserves actual byte/application facts. Empty replacement still performs the required truncate/flush. Recheck path attachment and source afterward. Namespace loss is non-success even if the original renamed/unlinked object received bytes; never reinstall it. This is not crash-atomic storage or arbitrary same-inode compare-and-write. Known interference always prevents success.

The earlier patched candidate used receipt-fed private mtime fields and an engine hook that tagged CodeEdit **last**; it is historical, not the selected stock recipe. [§13](../research.md#13-stock-target-save-finalization-research-2026-09-28) established that a custom saver returning non-OK cannot veto builtin path fallback (even an outside-project redirect), ordinary target Save applies all open scripts and may change unrelated history, and descriptor-backed `ResourceSaver.save` lacks ScriptEditor's document transition. [§14](../research.md#14-stock-post-persistence-saved-transition-research-2026-09-28) establishes the bounded direct existing-Callable route **after** descriptor persistence; neither ordinary Save, a custom saver, a broadcast signal nor CodeEdit-only tagging is a fallback.

## 3. Primitive A: guarded target-document saved transition

### Existing public ingredients and preconditions

Here "A" means attempt-owned **semantic** finalization, not `finalize_script_document(...)`, a new dedicated stock API, a private-method call by name, or a finalized native/bridge result schema. On the selected official engine build, obtain the canonical ScriptEditor with `EditorInterface.get_script_editor()`. Inspect its public `Object.get_incoming_connections()` for the **unique already existing** incoming `resource_saved` Signal and Callable whose receiver is that exact ScriptEditor. Retain the actual emitter Signal and Callable; verify `Signal.get_object()/get_name()`, `Callable.get_object()/is_valid()`, receiver instance IDs, incoming edge and emitter `get_signal_connection_list` before use. The observed emitter is EditorNode (flags `0`); reflected handler method metadata identifies `ScriptEditor::_res_saved_callback` **for audit only**. Never resolve or invoke that private method by string, use a binary symbol/private layout, walk an assumed editor-tree hierarchy, emit `resource_saved`, or invoke arbitrary connected listeners. Call only the **publicly returned actual Callable** with the exact held Script.

Before clearing the edited flag, establish all of:

1. The original authenticated connection/request/session/attempt slot is live and not expired, cancelled or consumed; the Script, ScriptEditorBase and CodeEdit retain the same instance IDs, resource path and unique still-open association. A retained Script or same-path reopened tab alone does not authorize tagging.
2. B has exactly the frozen post-complex-edit current version **and** desired text, and the frozen independently prepared saved version is unchanged; R is the exact intended source on the same Script. Equal text on a newer version is not enough.
3. The same attempt's native-only receipt proves complete descriptor write/truncate/flush/readback of the intended source; current no-follow project-path namespace attachment and target identity/source checks still hold. Failed, unknown, mismatched or lost-namespace persistence cannot authorize a tag.
4. The captured native edge/Callable still has its exact canonical receiver/emitter/topology and is valid; the held Script is the exact cached target, not a candidate that would require `ResourceLoader` fallback. Exclude any open built-in sibling Script with a parent-path collision: the stock handler may also tag/reload such documents. Capture/recheck the save-format profile and refuse unsupported document/effect topology conservatively.

### Selected order and effects

R synchronization precedes persistence and A: after **one** native CodeEdit complex text operation, compare B/current version and expected original R, call the bound `Script.set_source_code` method with the intended text, and read R back. Do not assign via `Object.set`/GDScript `_set` (which can reload), invoke `ScriptTextEditor::apply_code`/`update_exports`, or apply pending dragged-export properties. Descriptor-bound persistence follows; no additional source write occurs during the saved transition.

After all fresh guards pass, call `EditorInterface.set_object_edited(Script, false)` for the persisted guarded R, then **recheck** the entire still-open/identity/path/source/current-and-saved-version/receipt/namespace/cached-Script/edge binding immediately before direct `Callable.call(Script)`. Do not yield, pump events, focus/select a tab, issue a second write, dispatch a save or broadcast a signal between final guard and the native tag. The public edited setter has no intervening user callout in the tested route; retain a bounded, version-specific topology and reentrancy check rather than assuming arbitrary stock builds are safe.

The **stock native handler** matches the Script's actual edited Resource pointer and executes its combined target document tag: **CodeEdit current saved version first**, then ScriptEditorBase document `last_modified_time` from `FileAccess::get_modified_time(actual path)`. The guarded route does not supply a timestamp to private fields, change Resource path/cache identity, modify CodeEdit text/history, or numerically set/read Resource mtime. Stock list-name refresh is bounded UI bookkeeping; selecting/focusing a tab, notifying EditorData plugins and dispatching general EditorNode save are not part of this call. Path attachment is checked immediately before and independently after: external writers cannot be atomically excluded, and a later namespace loss prevents success.

This handler is **not pure or callback-free** after the native tag. It invokes `trigger_live_script_reload`: with an exact cached Script it can immediately run native language validation/dependency/cache paths even when runtime auto reload is disabled, record the path, and conditionally defer debugger reload. A missing cached target could instead enter `ResourceLoader` fallback and must be refused. No running-game hot-reload, unrestricted validator safety, effects confinement, export/Inspector refresh or project-wide compilation guarantee follows from the saved-state proof. Those independent stock validation/effect requirements keep T003 on hold. Do not suppress the callback's real effects by claiming finalization has no callouts; the narrower no-interstitial-callout claim is only **before/between** the stock CodeEdit/document tag operations on the audited build.

### Results, independent observation and failure

Record the attempt-local observed step facts: edited-flag clear, fresh pre-Callable guard, whether the Callable was entered/returned, observed CodeEdit current/saved versions, dirty state, D/R/B/identity/attachment and errors or unknowns. `complete`, `rejected` and `partial_or_unknown` describe **A only**, not edit success or a new final API shape. A rejected finalizer can follow changed B/R/D. A setter that succeeds before an invalidated recheck is **partial**; never report no bookkeeping or retry the old intent. A tag followed by new human text leaves the new buffer dirty; never restore, replay or overwrite it.

| Condition | Required result |
|---|---|
| Closed/replaced document, wrong Script/editor/CodeEdit, edge or cached Script, colliding built-in association | Reject before bookkeeping; if detected after edited-flag clearing, report partial. Never retarget. |
| Changed current **or** saved version, even equal desired text; newer human B or unexpected R | Refuse the tag, retain newer state; D may already have changed. |
| Failed/missing/unknown/mismatched receipt or changed/lost namespace | Refuse the tag without a saver fallback or replacement write; preserve actual application facts. |
| Reentrant work, cancellation or deadline before A | Refuse without starting bookkeeping; any later invalidation retains established effects. |
| Later invalidation/failure, including after a tag or stock handler effect | Report partial/unknown with observed steps; no rollback or cleanup write. |
| All bounded saved-transition guards/effects and independent readbacks pass | A may be complete **only as saved-state evidence**; independent validation/effect confinement and Rust's final reducer still gate edit success. |

After A, independently read actual still-open association, `EditorInterface.is_object_edited(Script)`, CodeEdit current/saved versions and dirty state, actual R/B, and Rust's fresh D/namespace evidence; do **not** substitute the Callable return or edited-flag setter acknowledgment. Private numeric Resource mtime and ScriptEditorBase document mtime are neither fabricated nor unconditional success witnesses. A native document timestamp update and continued coherent Save/Undo/Redo/reopen were behaviorally demonstrated for a standalone script across a natural timestamp-second change; future general cases remain subject to fresh capability and effect checks.

## 4. Primitive B: exact-source native GDScript validation

The following specifies the required validation behavior and records T002's patched-editor work; it is **not** a claim that the same effect-confined validator or automatic-effect guard exists in official stock Godot. P1 resolves only the saved transition. Stock native saved handling itself triggers language validation and possible deferred debugger reload, so its effects must also be addressed independently before T003.

### Inputs and output

`validate_gdscript_source(source, source_path, read_context, correlation)` runs synchronously on the selected editor main thread. Inputs are an immutable exact source string, exact project-confined `res://` root path, a native-only selected-project read context, and existing request/session/document identity plus purpose `preflight`, `post_change` or `unchanged`. No mutable global buffer is the implicit input. Compute SHA-256 from the actual supplied UTF-8 bytes; compare the integration's expected hash before invocation. The root target is already open/loaded; validation does not open or load it.

The engine exposure delegates to **`GDScriptLanguage::validate` → `GDScriptParser::parse(source, path, false)` → `GDScriptAnalyzer::analyze`**, with the scoped effect/dependency policy below. It marshals the actual return and root/dependency `ScriptError` records; it never uses reload, `can_instantiate`, silence in a log, or empty diagnostics as a validity witness.

Return exactly one status:

- `valid`: the requested parser/analyzer stages completed under the selected policy for this exact source/context, without errors.
- `invalid`: a completed validation rejected this source/context; retain root/dependency diagnostics and the failed parser/analyzer stage when supplied.
- `unavailable`: invocation incomplete, context/attribution invalid, disallowed effect, access failure, resource bound, wrong thread or reentrant invocation. Partial diagnostics do not turn it into valid/invalid.

Every result includes request/session/document binding, purpose, actual input path/hash/byte length, editor-clock start/end ticks, result/reason, dependency/context witnesses and `diagnostics_complete`. Diagnostics carry `origin: root|dependency`, confined path (or null with reason), source hash when actually read, line/column when supplied, category and message. Unknown dependency source is not assigned the root hash. Missing dependency proven by a confined read can yield a completed dependency error; an unreadable or unconfined dependency yields unavailable. Redact denied/outside-project paths; never disclose their source or raw absolute paths. Errors/messages appear only in the requested result, not incidental logs.

Limits: root and each dependency ≤512 KiB UTF-8; at most 32 distinct source dependencies / 4 MiB dependency bytes; at most 64 error records with messages ≤2048 UTF-8 bytes and paths ≤2048 bytes. Exceeding a needed bound yields `unavailable` with limit reason and safely retained partial diagnostics, not truncated source or false valid. Warnings/functions/safe-line UI data are not a new caller diagnostics API.

### Required effect policy: source analysis, not arbitrary evaluation

Allow the existing parser/analyzer, engine-native static type metadata, current project/global-class/autoload mapping lookup, confined read-only GDScript dependency text, normal parser/dependency-cache lookup/population and dependency-edge bookkeeping. Cache mutation is expected engine bookkeeping, not a purity failure. Do not clear global caches to simulate isolation.

T002 implemented a **patched-editor validation-call-scoped read/effect context** through the implicated GDScript parser/cache/analyzer paths and proved its confined dependency/effect behavior in 54 native cases. That implemented patched B is not a qualifying equivalent in official stock Godot; the following policy remains an independent stock requirement:

1. All dependency bytes are obtained through the trusted native integration's project-directory capability reader, with no-follow traversal and before/after identity/content checks. Resolve each relative dependency against the directory of the source containing that reference: the supplied root path for root references, and Godot's per-dependency source paths for transitive references. Resolve permitted project mappings to a confined `res://` path before reading. No absolute/user/network/embedded/remapped-outside-project fallback. Unsupported binary/remapped dependency representations are unavailable, not silently loaded.
2. A cache hit is usable only when attributable to the same project/path and current guarded input digest. A current `Script.source_code` getter does not prove cached parser/analyzer/shallow metadata was derived from that source generation. Stale/unattributed metadata cannot certify the proposed source. Reuse the engine's parser types; use call-local parser references where needed to analyze the root overlay/current dependency bytes without replacing a loaded target Script or globally clearing caches. Fresh per-call read witnesses remain distinct from a cache lookup.
3. Permit shallow GDScript metadata construction only without full reload, script instantiation or initialization. Intercept non-GDScript `ResourceLoader` resolution **before** invoking loaders (including exists/type hooks), full-script loading, and dynamic object-property `Variant::get/get_named` paths. This profile returns `unavailable/unsupported_effect` rather than invoke project code. Plain built-in value operations and engine-native static metadata remain allowed. Do not substitute guessed types or skip analysis and return valid.
4. No user method, tool/static initializer, scripted constructor/getter, arbitrary loader/callback, process/network action, source write, root R/B assignment, document save or project scan is permitted as an effect of this call. `@tool` syntax alone is not execution or an automatic rejection; a resolution path requiring an excluded effect is. Unsupported effectful validation is a truthful capability refusal, not a new evaluation permission prompt.
5. Capture and recheck dependency identities/hashes and relevant project/class/autoload/remap context used by the invocation. Changed/missing witnesses make the result unavailable/invalidated. The result describes an observed context, not an atomic snapshot or project-wide compilation.

T002's patched GDScript-owned validator implements the concrete call-scoped parser/cache/analyzer interception while reusing Godot's compiler, rather than a second compiler, global execution sandbox or service. Its patched-editor acceptance remains complete. What is **not** established is a stock-equivalent exact-source validator with this confinement, or control of ordinary/edit-generated automatic validation and export work, the native saved handler's validation/deferred reload, and queued effects. These independent stock requirements keep T003 on hold. The bridge cannot supply executable read callbacks. Existing exclusion of hostile code already executing inside the editor/same-UID malware remains unchanged.

### Guarding the ordinary editor path

The historical companion engine guard was proposed because successful ordinary non-tool `_validate_script` can copy B into R and call `update_exports`; `apply_code` is broader still. The selected saved-state route has **no** such stock engine guard. Any T003 design must separately constrain target validation/function-discovery callbacks caused by the agent edit, prevent duplicate R/export/dragged-property application, and account for the native saved handler's own `trigger_live_script_reload` validation and conditional deferred debugger path. Explicit supported `Script.set_source_code` remains the only planned R synchronization step.

Bind queued automatic work to the actual target and agent-produced CodeEdit version. Any eventual effect guard must consume/cancel redundant work already satisfied by explicit results or leave it restricted until drained; it must not release an unrestricted delayed reload/export callback caused by this attempt. A subsequent independent human source change invalidates the attempt and retains normal Godot handling for newer work. Do not globally disable validation, block human typing, rewrite newer text or clear unrelated editor state. No **agent-initiated automatic** callback may mark a buffer saved outside the selected guarded post-persistence transition; ordinary independent human Save retains its normal behavior.

Inability to establish stock effect coverage is a non-success/unsupported implementation result, not permission to proceed. The historical patched hooks are not selected as an automatic T003 fallback.

### Placement in the edit flow

For changed intent, run B on proposed source during preparation to refuse invalid/unsupported-effect inputs before changing B or history. Then freshly recheck all mutation guards; preflight is not permission for a delayed edit. After source application, persistence and A, read the actual resulting B/R and invoke B again with that exact source as `post_change`. This second result is the required post-change parse witness. Dependency/context changes can still produce invalid/unavailable after an earlier valid result; report applied-unverified and do not force convergence.

For unchanged requests, skip proposed-source preflight and run one `unchanged` validation with independent verification, without native text mutation, writer, finalizer, saved tagging or history entries.
