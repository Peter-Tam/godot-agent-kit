# Native Clean-Document Closing Integration

**Status:** T001 is complete with [native and full affected-suite acceptance](../quickstart.md#9-t001-native-boundary-acceptance-2026-10-02) for the revision-3 family, shared-slot internal owner and real protected-source validation. Public closing and its caller/supervisor exchange remain T002 work and `close_gdscript` stays false. This contract uses public Godot APIs and the generated GDExtension ABI, not an engine patch or private editor-field access. Earlier [research](../research.md) remains historical evidence.

## 1. Responsibilities and matched native family

Rust owns checked intent, fresh target selection, expected-basis comparison, source-only validation children, one-shot authorization, caller deadline and public terminal reduction. The addon owns authenticated transport, the existing operation slot and response lifetime. Native C++ owns exact document/file/effect guards, one stock close call, attempt-local continuation witnesses and attributable native facts. Neither native nor addon returns a product success verdict.

Select native API revision **3**, authenticated by private bridge **v5**, retaining metadata key `godot_agent_kit_native`, bundle `editor_integration.gdextension`, library `libeditor_integration.macos.arm64.dylib` and entrypoint `editor_integration_library_init`. Revision 3 retains existing edit/open behavior and adds the close family/lifetime contract. The exact engine/hash/generated ABI, source/build ID and library provenance remain mandatory. Update builder method-hash extraction, manifest, plugin family/revision validation, native registration, Rust private consumers and fixtures in the same compatibility cutover. Old native revision 2 must not be silently treated as the new family; unavailable native integration leaves observation/discovery available with their unchanged meanings.

The builder obtains the exact `ScriptEditor.close_file(String) -> Error` MethodBind hash and needed public signal/getter hashes from the pinned executable's generated extension API. Runtime verifies actual supported ScriptEditorBase signals. A missing method, wrong return/signature/layout or unsupported signal/context disables/refuses closing rather than invoking arbitrary names or private fallbacks. No artifact rename, alternate binary alias or new dependency is needed.

| Private native entry | Arguments / responsibility |
|---|---|
| `close_inspect` | `(path, correlation)`; reserve the shared native owner and inspect target/cache/open association passively. Correlation is checked request/session/editor expiry. No source mutation, load, selection or validation. |
| `close_prepare` | `(request_id, captured_source, capture_and_basis)`; independently pin/read-check target file and freeze target/complete bounded protection/effective-context facts. No lifecycle effect. |
| `close_advance` | `(request_id, guard_sha256, receipt_bindings)`; consume exactly one authorization, recheck all guards and invoke one native close. No arbitrary stage/method input. |
| `close_status` | `(request_id)`; read this attempt's bounded native facts and continuation ledger for the addon frame loop. Never trigger or replay work. |
| `close_verify` | `(request_id, purpose)` where purpose is `recognition`, `post_close` or `survivor`; acquire fresh native Resource/identity/protection/selection facts, separate from the ordinary target collector. |
| `close_recheck` | `(request_id, purpose)` where purpose is `pre_close`, `recognition` or `post_close`; compare current file/roster/source/configuration and relevant frozen evidence. |
| `close_finish` / `close_abort` | `(request_id)`; terminalize only this attempt, with actual discard/effect knowledge. No rollback/reopen/Save/source cleanup. |

Existing native `close()` is session teardown and remains distinct from script closure. Private registration does not create extra public tools. No arbitrary client-supplied callbacks, source overrides or success Booleans are accepted.

The exact private preparation object is the [bridge projection](bridge-protocol.md#3-exact-request-tuples-and-stage-order): `capture_and_basis` has only `project_device`, `project_inode`, `target_device`, `target_inode`, `source_sha256`, `utf8_bytes`, `basis`; compact `basis` has only `script_instance_id`, `editor_instance_id`, `buffer_instance_id`, `current_version`. IDs/devices/inodes/version are canonical decimal strings, length a bounded nonnegative integer and digest lowercase SHA-256 hex. Rust must compare the independent capture with the checked prior basis before prepare/authorization; native independently compares current exact D/R/B and the original identity/version against that immutable capture/basis.

`receipt_bindings` uses the bridge's exact compact identity/source/guard/context keys, sorted over the complete protected set. Actual completed-valid state, per-URI fences, caller interval and owned-child cleanup remain supervisor evidence, not a client-controlled native `valid` flag. Native rejects missing/extra/duplicate/mismatched bindings. Native returned facts use the closed projection in [bridge §5](bridge-protocol.md#5-strict-response-projection); no undocumented additional result fields or public success verdict.

## 2. Shared ownership and implementation shape

Extend the existing native `Session` owner variant from edit/open to edit/open/close; retain the one addon `_active` operation slot shared with observation/discovery. No second scheduler, lease service, queued close or retry store. The close attempt has one coherent state enum plus monotonic stage/effect facts, not several independently toggled lifecycle Booleans permitting impossible states.

Use a close-owned `script_close.cpp` and private declaration/header support as needed. Extract only actually shared source/effective-context/profile acquisition from existing `open_context` into `editor_context`; opening's selected-current wrapper and behavior remain distinct. `document_guard` remains the descriptor/namespace/document association owner. Save formatting, source application, mtime restoration, saved tagging and persistence stay edit-only. Do not make closing call edit/open state machines or copy their lexical scanners.

Every callback stores the owning session/request generation and exact observed object ID, never a reusable path-only token. Registered native Callables and their data outlive all entered callbacks; cancel/disable disconnects them only when safe and never destroys their data while the callback is running. Reentrant teardown marks terminal/closing state, refuses new entry and defers owned destruction until the outermost native call returns. Existing edit/open ownership regressions must still pass on the new family.

The native `phase` vocabulary is exactly `inspected`, `prepared`, `entered`, `returned`, `settling`, `settled`, `terminal`. `inspected` may finish recognition or prepare; `prepared` may enter the single effect after authorization; `entered` becomes `returned` only after the actual call returns; a returned call becomes `settling` for outstanding surviving validation obligations or `settled` when none remain. The ledger alone can move settling to settled when every required editor's latest attributable required visit has a matching completion. For a nonterminal attempt with intact preservation guards, a later attributable required visit makes the continuation pending again and moves `settled` back to `settling`; it does not renew the lease, authorize another close or revive a terminal attempt. Any state may request termination, but entered calls/callbacks retain ownership until return. `entered`, `invalidated`, old-document removal and discard in the returned projection are monotonic evidence facts, not independent lifecycle switches. An error return must not be confused with absent entry or observed removal; terminal state does not erase known effects.

## 3. Inspect and already-closed recognition

Authenticate and resolve the actual project/session/path before inspecting source. The Rust side independently establishes an existing regular confined target; missing disk while a buffer survives is a missing/evidence refusal, never already closed. The native inspector uses existing public open-script/editor arrays, exact ScriptEditorBase/CodeEdit association and passive `ResourceLoader.get_cached_ref`. A getter failure, duplicate path, unsupported type or mismatched association is not absence.

A confirmed already-closed valid target takes the no-effect recognition branch. Do not call `close_file` as an existence probe, prepare a close context, validate any source, select/open/load the target or touch history. Preserve safely available D and cached R with existing per-source limitations. A supplied checked basis does not authorize replacement state; matching identity/session/file checks precede recognition, while an obsolete open-buffer version is explicitly not applied to the closed state. Null expected basis is valid for recognition, but cannot authorize a later open-document close.

Recognition receives a fresh ordinary target observation and native/lifetime/file recheck. Unknown open state, lost target attribution or a detected intervening open/identity change prevents a current already-closed claim. Do not automatically switch a recognized-closed attempt into an effectful close if a human opens it.

## 4. Immutable target and protection preparation

### Target

For effectful closing, the existing prior clean observation basis must match current exact project/session/path, disk identity, Script/editor/buffer IDs, source commitment and current buffer version. Independently acquire agreeing D/R/B, attributed buffer clean state and Resource edited=false; source equality alone never proves either flag. A same-text close/reopen has a new editor/buffer identity and must not inherit the old authority.

Open the existing target read-only through the current project/parent/leaf capability and no-follow guards. Retain descriptors, independently compare the complete captured bytes and identity, and check namespace attachment and permissions at each applicable boundary. Do not require writable access, Save-format eligibility, `ResourceSaver`, writes, truncation, fsync, mtime restoration or saved-state tagging. Native source copies serve immutable comparison only, not setters or fabricated postconditions.

Use actual bound native GDScript/ScriptEditorBase/CodeEdit APIs and the supported internal editor association. Do not inspect by switching to a non-selected tab. The target must satisfy the existing bounded source/effect profile (standalone LF UTF-8, no unsafe dependency/tool/export/static/dynamic-property contexts) but **not** a parse-validity test: the safe syntax-invalid and read-only controls remain mandatory positives. A previous valid parse is not required to close unchanged clean text.

### Complete bounded set of potentially visited remaining documents

Capture all remaining supported open standalone GDScripts through the same public associations. The [data model bounds](../data-model.md#2-fixed-supported-profile-and-bounds) apply: at most eight script documents including target, 512 KiB aggregate remaining R==B source and 256 KiB aggregate non-source effect metadata. Refuse unsupported mixed/custom/external-editor contexts or oversize sets before effects; never omit a candidate or guess the private history stack. The bounded positive two-document workflow remains required.

For every remaining document:

1. Establish exact project-local path/file and Script/editor/buffer identity; independently read equal R and B; capture document-attributable dirty state, Resource-edited flag, current/saved versions and native Undo/Redo availability. Dirty R==B may be preserved; dirty R!=B or unknown state refuses. No requirement to make its D equal unsaved R/B, Save it or tag it clean.
2. Apply the existing source lexical profile and passive compiled tool/base/property/method/ClassDB/global/autoload/warning checks from the [opening contract](../../003-open-project-gdscript/contracts/native-integration.md#2-supported-new-open-profile). Retain current limits, typed fingerprints and rejection of pending-export-capable property profiles. Do not assert an unobservable `pending_exports_empty` value.
3. Freeze the complete roster, actual selected identity, effective configuration and per-document guard commitments. Include actual configured native idle-parse delay in the effective guard. A delay/configuration that cannot fit the remaining original lease must refuse before closing instead of knowingly starting an unverifiable continuation; never change preferences to obtain eligibility. Ordinary scheduler delay can still cause truthful post-effect timeout.
4. Return private captured R==B source for exact-source preflight only. Protected source/path/hash/diagnostic details stay out of the public result and incidental logs. Do not load a dependency or acquire an outside-project source.

The native method can visit more than one tab through history and list sorting; checking only the closing target or only the current tab misses source-established paths. The complete bounded candidate set avoids private navigation-state access. Roster/selection changes between capture and dispatch invalidate the preparation, not permission to expand it automatically.

## 5. Private exact-source validation and one-shot entry

The existing Rust supervisor uses the current one-shot stock validator with purpose `close_context`, one remaining document at a time, under the same original caller cutoff. The live target is not compiled or reparsed to validate a close. Require actual per-URI diagnostic/parser-symbol fences, source/effective-context identity and owned-child reap/cleanup; a matching hash without completed validation is insufficient. Preserve the inherited stock local-LSP endpoint limitation and no-log/private staging behavior; do not introduce an execution tool or new isolation layer.

The private receipt binds close request/session/target, protected path and Script/editor/buffer identities, source hash/length, native document guard hash, validator context hash and completion interval/cleanup. Wrong purpose, duplicate/missing document receipt, source/context change or failed/unavailable validation cannot authorize closing. The aggregate guard is recomputed in Rust using the existing typed `F`/`E` encoding with `godot-agent-kit/close-context/v1`; the [data model](../data-model.md#9-private-interface-contract-shared-by-design-artifacts) defines what is committed. Collection clocks and helper progress are not part of an immutable guard.

Immediately before the sole effect, recheck expected target/file/source/dirty/current/saved/Resource-edited facts, exact open roster and selection, every protected document and effective/compiled profile, original session/owner and remaining deadline. Ordinary human input cannot interleave a same-main-thread guard and synchronous call without event pumping; do not pump events. The model does not claim atomic exclusion of arbitrary external filesystem writers. Known namespace/source/context invalidation always defeats authorization and later success.

The parent records possible application before releasing the authorization. Native marks `closing: entered` before the bound `ScriptEditor.close_file(original_path)` call. This API is inherently discard-capable, so the final guard is mandatory even if earlier checks were clean. There is no second close call, retry on `ERR_FILE_NOT_FOUND`, retarget by focus, Save/discard prompt acceptance or buffer-freeing fallback.

Record actual call return/error and lifecycle observations separately. `OK` is not verified success; a callback, history transition or partial native failure can leave known effects even if final state is unavailable. The old target buffer's disposal is native lifecycle participation, not a source UndoRedo entry.

## 6. Automatic revalidation witnesses

The user-approved FR-005 exception permits normal close-triggered validation of unchanged already-loaded source, not explicit repair/reparse. Its deferred lifetime is part of this attempt.

Before entry, connect bounded non-mutating native witnesses to `ScriptEditor.editor_script_changed` and each exact protected ScriptEditorBase's actual `edited_script_changed`. The [pinned source chain](../research.md#42-native-navigation-source-application-and-validation) and stock probes establish these events. Runtime absence or unsafe attribution of a required signal refuses before entry. The signal is observed, never emitted by the product to manufacture completion.

During the synchronous close, record each actually visited protected editor and its source/version/identity binding. Native selection of an unadmitted document invalidates the attempt. Visits to the closing target do not become surviving validation obligations once its actual editor/timer is destroyed. After native return, receive real completion events for the surviving visited set; pre-entry events and events from replacement instances never count. `required_editor_ids` is exact and monotonic for the attempt. `completed_editor_ids` represents only currently satisfied obligations for each editor's latest attributable required visit; it is not historical and is not monotonic. A later attributable visit keeps the editor in `required_editor_ids` but removes it from `completed_editor_ids` until a new matching attributable completion occurs. The continuation is complete only when every required editor's latest outstanding visit has a matching attributable completion, with all frozen preservation checks intact. Coalesce repeated unchanged visits only according to the native idle-timer semantics; historical earlier completion must not satisfy a renewed obligation.

The callback is evidence acquisition only. It does not call validation, modify source, select a tab, suppress a timer or invoke another close. Freeze and recheck identity/source/flags before accepting a completion. The ordinary `name_changed`/built-in update callbacks precede `edited_script_changed`; native list sorting resets its sort flag, and any observed later selection visit must still be included in the attempt's ledger. Do not infer quiescence of unrelated editor activity from a fixed frame count. A final unchanged roster/context/source recheck and matching complete ledger are required before independent verification can pass.

The addon may hold one `close_wait` response and examine `close_status` from its existing per-frame owner. This waits for already-scheduled native evidence, not human convergence and not a new service. It must remain bounded by the original lease and report pending/unavailable/invalidated evidence truthfully. On human edits after closure, keep the new text and invalidate old protection evidence; do not cancel the human's ordinary editor activity or restore the prior source to pass the old request.

## 7. Independent verification and truthful terminal state

After `closing` returned and the required continuation ledger completed/not-applicable:

1. Acquire a fresh ordinary observation for the original target under the same owned attempt. Independently confirm no open target buffer; absence of a getter result alone is not confirmation. A new same-path buffer means final closure is unverified, never a new close destination.
2. Rust independently reacquires D and checks the original file/namespace/source. Native performs separate exact descriptor/namespace rechecks. No target source write occurred or is permitted.
3. Release the attempt's target-only Resource holds before the ordinary post-close R read. If R remains genuinely loaded, observe its actual source/identity/edited state and require unchanged source. If genuinely absent, report unloaded explicitly. If retained state cannot be read/attributed, do not equate it with unloading. Do not force-load or unload to produce a preferred result.
4. Recheck every protected document's actual R/B, identity, current/saved versions, dirty/Resource flags and history availability and the native continuation ledger. No changed or missing guard can be concealed by later equality.
5. Verify selection: for a non-selected target the exact before-selected identity remains selected; for a selected target ordinary native fallback is allowed and reported. Do not select another tab to establish this evidence or steal focus back after human input.

Actual before/immediate/post-close facts retain their own collection intervals and validity. B and buffer dirty state become not applicable only after independent confirmed closure. A native receipt is not a replacement for the ordinary collector, Rust D or independent preservation checks.

Roster checks are phase-aware: before entry the entire prepared roster must match; afterward the expected roster is exactly that roster **minus the original target editor/buffer**, with every protected identity unchanged. That one authorized removal is not invalidation. Any additional removal, new/reopened target or replacement document invalidates postconditions. Recompute fresh protected-document guards and actual post-close state, rather than requiring the pre-close aggregate hash to equal a post-close hash that necessarily lacks the target. Native fallback selection is the separately observed authorized exception for a selected target, not a guessed replacement for missing evidence.

For a newly closed result, a present cached R must still be the original admitted Script identity with unchanged source; a different same-path Script is replacement/invalidation, not retained evidence even if bytes match. A genuinely absent R is reported unloaded. Already-closed no-effect recognition instead reports actual current cache facts without certifying a prior open identity as applied.

`close_finish` and `close_abort` only clean owned handles, signal connections and state. They must never reopen, reclose, Save, revert, retag or clear unrelated history. A refused/busy attempt has no source/history effect and cannot run later. Known closure or selection effects survive timeout/cancellation/loss as `applied_unverified`; uncertain authorized entry remains `effects_unknown` unless a genuine terminal pre-entry discard is obtained. Late facts cannot upgrade the already-delivered result.

On disconnect/disable/expiry, prevent any new product entry/stage. Retain a synchronous entered close/callback's ownership and references until it returns. If the call has returned but ordinary validation is still pending at terminal expiry, disconnect the owned evidence ledger and release safely, reporting unverified effects. Do not kill the editor or claim the ordinary Godot continuation was cancelled. There is no queued product close left to apply to newer work.

## 8. Threat boundary and required proof

Retain the [existing local-editor threat model](../../003-open-project-gdscript/research.md#6-scope-correction-and-callback-limitation): hostile same-UID processes and malicious code already running inside Godot are not a newly supported adversarial environment. Known unsafe extension/context and detectable interference must still refuse or prevent success. Do not introduce generic callback-registry isolation, plugin shutdown, blanket approval or a fresh-editor product prerequisite. This contract does not claim that arbitrary reentrant extension code can never mutate/falsify buffers during Godot's own close notification.

This limitation does not excuse the demonstrated ordinary dirty-buffer R application. The bounded effect profile, full candidate set, fresh entry guards and native completion witnesses address that in-scope failure. Runtime races must exercise ordinary human changes before entry and after the synchronous close, as well as reentrant kit cancellation/disable/ownership safety without assuming rollback or freeing entered callbacks.

Required implementation evidence includes selected/non-selected/last-tab positives; retained and naturally unloaded R; safe syntax-invalid/read-only/empty targets; dirty/equal-dirty/stale/missing-basis/profile/limit refusals; unrelated dirty R==B plus real Undo/Redo; the R!=B refusal regression; history-back/sort paths with multiple protected documents; wrong/missing/premature/replacement validation events; source/file/roster/session/configuration races; exactly-once close, overlap and no late application; interruption before/after entry and while waiting; fresh reopened-buffer preservation; independent D/R/B/dirty evidence and actual owned-window proof. No test may relabel a raw fixture close as the product's guarded close.

The shared revision-3/v5/owner/context-helper change requires complete affected existing suites and the final close cumulative A–E/durability/export gate described in [quickstart.md](../quickstart.md). Compile normal and separate fixture-fault artifacts through existing provenance rules; fault Callables belong only to the separate test artifact. No new test framework, CI provider or implementation task is created by this contract.
